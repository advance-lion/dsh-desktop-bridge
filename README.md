# 桌面兜底桥 · Desktop Fallback Bridge

**让每一个 DSH 会话都能"用手"，而不只是写代码。**

结构化能力优先 · Computer Use 兜底 · 单桌面串行

![License](https://img.shields.io/badge/license-MIT-blue)
![Platform](https://img.shields.io/badge/platform-Windows-0078d4)
![Requires](https://img.shields.io/badge/requires-dsh--orb-6b46c1)

## 问题

你装了 [dsh-orb](https://github.com/mini-yifan/dsh-orb-cordis)，悬浮球能用 Computer Use。可是回到**普通会话**让它点一下某个软件，它做不到——GUI 工具只挂在独立的 `computer-use` 预设里。

于是每次都变成：切模式 → 重新讲一遍上下文 → 做完再切回来。

**这个插件只做一件事：给所有会话一个统一的"请人去操作桌面"的入口，并且保证同一时刻只有一个人在动鼠标。**

---

## 能力

| | |
| --- | --- |
| **全会话可委派** | 装一次，标准 / 工作台 / 自定义预设都能用，不用切模式 |
| **结构化优先** | 文件、shell、MCP、API、Skills 能做的，绝不占桌面 |
| **`@computer` 显式通道** | 用户打标签就无条件执行，不靠模型猜 |
| **单桌面串行** | 任务从提交到结束独占桌面，后来者 FIFO 排队 |
| **跨进程互斥** | 第二个 DSH 进程会拒绝动手，而不是和你抢鼠标 |
| **与悬浮球互斥** | 桥接工作时悬浮球会话让位，反之亦然 |
| **随「停止」一起停** | 停掉那一轮对话，桌面工作会话一并中断 |
| **预算与自检** | 单任务限时；缺依赖时开机就说清怎么修 |

## 边界（先读这段）

> **本插件不含任何 Computer Use 实现。** 截屏、点击、输入全部由 [dsh-orb](https://github.com/mini-yifan/dsh-orb-cordis) 提供。这里只做**桥接、排队、权限和边界控制**。
>
> 所以：**请先装 dsh-orb**，否则 `computer_task` 会拒绝执行并提示你安装。

- **不做观察类任务。** "我现在在干嘛""屏幕上是什么"这类问题，shell 截屏 + 读图更快更准，还不用占桌面。GUI 的价值是**动手**，不是**看**。
- **不抢占。** 桌面忙时排队或超时，不会打断正在跑的任务。
- **不跨机器。** 控制的是宿主桌面，不是浏览器所在设备。
- **不装作能自动化一切。** 终端类应用、DSH 自身、需要管理员授权的系统弹窗不在范围内。
- **目标窗口被遮挡时可能点错。** 见文末「已知问题」。

## 快速开始

```sh
dsh plugin add dsh-orb              # 1. 先装执行后端
dsh plugin add dsh-desktop-bridge  # 2. 再装桥
```

然后直接说：

> 帮我在计算器里算一下 7×8

要它**立刻动手、别再权衡**时，加个标签：

> **@computer** 把那个弹窗点掉

## 什么时候会真的用上它

判据取自 Codex：**当任务依赖一个"光看文件和命令输出无法确认"的图形界面时**，才用 Computer Use。

| 需求 | 走哪条 |
| --- | --- |
| 改代码、读文件、批量重命名 | 文件 / shell |
| 有插件、MCP、API、Skill | 结构化接口 |
| 网页内容 | 抓取 / 浏览器自动化 |
| 只能点界面才能改的设置 | **本插件** |
| 只在 GUI 复现的 bug | **本插件** |
| 跨多个应用串起来的流程（一次一段） | **本插件** |
| 看屏幕 / 问"我在干嘛" | 截屏 + 读图，不走这里 |

坦白讲：**在 full-access 的 Windows 上，它会被用得比你想象中少**——`pwsh` 能调 Win32、能截屏、能读 UI Automation，观察和操作几乎都能包掉。

这不是缺陷，是设计意图。它不可替代的场景只有三个：**shell 不可用、目标应用没有自动化接口、或者你明确要它动手**。

## 抢占怎么处理

一台机器一个桌面、一个鼠标，所以：

```text
提交任务 → 排队 → 获得租约 → 桌面工作会话 → 释放 → 下一个
```

- **任务级独占，不是"每次点击加锁"。** 否则会出现 A 打开表单、B 切走窗口、A 在别人的窗口里输入。
- **默认 FIFO**，模型无权插队。
- **跨进程**：用 OS 级独占句柄（Windows 命名管道）声明控制权，抢不到就拒绝执行。
- **随停止中断**：你在聊天里点停止，桌面工作会话也会被中断。

## 配置

`cordis.patch.yml` 的 `config`：

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `mode` | `auto` | `auto` 按判据判断；`explicit_only` 只认 `@computer`；`off` 关闭 |
| `workerPreset` | `computer-use` | 工作会话用的预设，由 dsh-orb 提供 |
| `maxWaitSeconds` | `300` | 桌面繁忙时最长排队时间 |
| `maxRunSeconds` | `600` | 单任务最长占用桌面时间 |
| `maxTasksPerSession` | `1` | 每会话同时在飞的任务数 |
| `workerProvider` / `workerModel` | 继承 | 工作会话模型，**必须支持图片输入** |

## 兼容性

| 项 | 说明 |
| --- | --- |
| DSH | 0.2.x（桌面版实测） |
| 平台 | Windows 首发，其它平台未验证 |
| 依赖 | **dsh-orb ≥ 0.2.0**（提供 `computer-use` 预设） |
| 耦合 | 只依赖预设 id 与 `screen-owner` 记录，**不 import dsh-orb 代码**，升级不会在加载期崩 |

预设被改名或缺失时，插件在启动自检里说明，并持续告诉模型"为什么不能用、怎么修"——不会等你要求操作桌面时才撞墙。

## 已知问题

- **worker 可能点到被遮挡的窗口。** 首次真实运行时，计算器被其它窗口挡住，几个点击落到了编辑器上，误开了一个标签页（已由它自己关闭）。目标窗口不在前台时，先手动把它带到最前，或让任务里明确"先激活该应用"。
- **没有原生状态面板。** 状态通过 `computer_desktop_status` 查询，尚无全局面板。
- **没有"停止当前任务并立即交接"**，只有排队取消、预算超时与随对话停止。
